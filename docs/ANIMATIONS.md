# Подключение пиксельных анимаций

## Имена действий

Действия, состояния и анимации используют глаголы в базовой форме:
`sit_idle`, `stand_idle`, `walk`, `run`, `sleep`, `clean`, `dig`, `swat`,
`meow`, `eat`, `poop`, `startle`, `sneak`, `jump`, `hide`, `drag`, `fall`, `recover`.
Переходы поз: `sit_down`, `stand_up`, `lie_down`, `sit_up`.
Точка когтей: `start_sharpen_claws → sharpen_claws → end_sharpen_claws`.
Катание в песке: `start_sandbath → sandbath → end_sandbath`.
Фазы действия называются `start_<действие>` и `end_<действие>`:
например, `start_clean → clean → end_clean` и `start_hide → hide → end_hide`.
Полный список находится в `src/animation_node.py`.

Те же имена используются в JSON, папках с готовыми кадрами, графе и сценариях.
Охота на курсор (`hunt`) — составной сценарий; её цикл подкрадывания — `sneak`.
Сценарии также используют базовую форму: `beg_food`, `inspect_notifications`,
`run`, `menu_meow`. Исходные папки художника сохраняют свои названия.

Старые имена (`sleeping`, `running`, `cleaning`, `hunting`, `pounce` и другие)
заменены без алиасов. В сторонних сценариях и манифестах нужно обновить
ссылки: например, `AnimationNode.SLEEP`, `AnimationNode.SNEAK`,
`AnimationNode.JUMP`, `PetState.CLEAN`, `manager.start("hide")`.

## Быстрая замена существующих клипов

Добавьте `assets/animations.json`. Манифест не обязателен: без него используются
старые `assets/<имя узла>/*.png`, масштаб 0.3 и длительность кадра 50 мс.
Пример смешанного набора находится в `examples/animations.json`.
Он иллюстрирует пути: соответствующие PNG нужно экспортировать самостоятельно.

```json
{
  "version": 1,
  "clips": {
    "sit_idle": {
      "directory": "pixel/idle",
      "pixel_art": true,
      "scale": 3,
      "frame_ms": 100
    },
    "walk": {
      "sheet": "pixel/walk.png",
      "frame_size": [32, 32],
      "count": 4,
      "pixel_art": true,
      "scale": 3,
      "durations_ms": [80, 80, 100, 80]
    }
  }
}
```

Остальные клипы продолжают загружаться из старых папок. Для полностью нового
набора можно вынести `pixel_art`, `scale`, `frame_ms` в объект `defaults`.
Defaults применяются и к клипам, которые не перечислены в `clips`: не включайте
глобальный пиксельный масштаб, пока используете старые большие изображения.
Настройки конкретного клипа имеют приоритет над defaults.

## Контракт экспорта

- PNG с прозрачностью; исходный персонаж смотрит вправо. Левое направление
  зеркалируется проигрывателем и кэшируется.
- Размер холста одинаков для всех кадров клипа. Для плавной смены поз используйте
  одинаковый холст и положение стоп во всём наборе: приложение удерживает низ окна.
- Папка: файлы `.png`/`.PNG` сортируются естественно: `1`, `2`, `10`.
- Спрайт-лист: одинаковые ячейки без промежутков, порядок слева направо,
  затем сверху вниз. Размер листа кратен размеру ячейки. `count` ограничивает
  количество кадров, позволяя оставить пустые ячейки в конце.
- `frame_ms` — положительное целое число миллисекунд. `durations_ms` задаёт
  время каждого кадра, имеет приоритет и должен совпадать с количеством кадров.
- `pixel_art: true` включает nearest-neighbor и требует целого `scale >= 1`.
  Это сохраняет исходные цвета без сглаживания. Дробный системный DPI Windows
  стоит отдельно проверять на целевом мониторе.
- Пути разрешаются относительно `assets/` и не могут выходить за этот каталог.
- Максимальный размер отрисованного кадра — 16384 пикселя по каждой стороне.
- Зацикливание и необходимость движения определяет граф поведения, а не JSON.
  Смена рисунков не меняет семантику сна, падения и ходьбы.

Повреждённый кадр или неверное описание отклоняет весь клип с диагностикой:
кадры не пропускаются молча. Ошибка сценария отменяет его таймеры и возвращает
питомца в idle. Отсутствие стартового idle показывает понятную ошибку запуска.
Для применения изменений ресурсов перезапустите приложение.

## Новая поза / новый сценарий

Замена существующей позы требует только PNG и манифест. Для совершенно нового
узла добавьте имя в `src/animation_node.py`, метаданные и входящие/исходящие
переходы в `src/animation_graph.py`, затем используйте его из сценария.
Одна запись JSON не регистрирует новый узел графа. Новые сценарии по-прежнему
добавляются отдельными файлами в `behavior_plugins/`.

Загрузчик (`animation_assets.py`) отвечает за проверку, декодирование и кэш.
Проигрыватель (`animation_player.py`) — за время кадров и однократный сигнал
завершения. Граф (`pet_animator.py`) — за переходы и прерывания. Сценарии
(`behavior_runtime.py`, `behaviors/`) — за действия и принадлежащие им таймеры.
Кэш ограничен приблизительно 64 МиБ отрисованных пикселей, с вытеснением LRU.
Текущий клип, исходные изображения во время декодирования и накладные расходы Qt
в этот лимит не входят. Очень большие клипы проигрываются без сохранения в кэше.

## Проверка перед интеграцией

```powershell
python scripts/validate_assets.py
python scripts/validate_assets.py E:\Assets\DesktopPet --strict
python -m unittest discover -s tests -v
```

Первый вызов проверяет все узлы и все записи манифеста. Отсутствие `yawn`
допустимо без `--strict`, поскольку встроенные сценарии его не используют.
Валидатор не считает произвольные папки новыми анимациями.
В установленном наборе все узлы, включая `yawn`, имеют ресурсы:
[подробности и временные подстановки](ANIMATION_PACK.md).
PyInstaller уже включает весь `assets/`, поэтому отдельные правила для JSON
или спрайт-листов в сборке не нужны.
