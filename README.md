# Desktop Pet

`stand_idle` использует спокойные кадры «3. Alerted2»:
`002 → 003 → 004 → 003`, по 240 мс. Шевелятся уши; корпус и лапы не смещаются.

`drag` при захвате использует кадры прыжка `002 → 003 → 004 → 003`
(880 мс на цикл): двигаются хвост, задние лапы и немного корпус.
После отпускания `fall` однократно продолжает прыжок тремя воздушными кадрами
(210 мс). Если земля ещё не достигнута, последняя поза удерживается.
При касании земли `recover` однократно проигрывает четыре кадра приземления
(360 мс), затем возвращает манула в стойку. Перемещение задаёт физика;
встроенное смещение исходных картинок компенсируется при импорте.

`sharpen_claws` раз в 3–6 минут подбегает к одному из краёв экрана и точит когти:
`start_sharpen_claws → sharpen_claws → end_sharpen_claws`. Основной цикл длится
4–8 секунд и заканчивается на границе оборота. Затем манул отбегает от края.
Курсор свободен; обычный `swat` по курсору остаётся одноразовым.

`sandbath` раз в 4–7 минут запускает `start_sandbath → sandbath → end_sandbath`:
манул укладывается (000–002), катается в цикле (003–008) случайные 4–7 секунд,
затем встаёт (009–014) и возвращается в idle. Кадры идут по 130 мс.
Выход ждёт окончания текущего оборота; занятые действия не прерываются.

При запуске манул выбегает из-за левого или правого края экрана в сценарии
`enter`. После `hide` он так же возвращается бегом из-за выбранного края.
В начале `hide` манул постепенно убегает за край и скрывается целиком,
прежде чем начинается пауза за экраном.
Видимая часть появляется постепенно; на время входа окно обрезается по границам
своего экрана, в том числе при нескольких мониторах. После входа манул садится.

Консоль по умолчанию скрыта. Откройте её через ПКМ по манулу → `Open console`.
Журнал состояний и ошибок находится над отдельной строкой команд: новые записи
не меняют вводимый текст. Enter выполняет команду; `help` выводит список.
Закрытие консоли сохраняет журнал и набранную строку, приложение продолжает работу.
В журнале хранятся последние 500 строк.

Настольный питомец на Python 3.10+ и PyQt6. Для запуска нужны локальные ресурсы
`assets/`: они исключены из Git и не входят в чистый clone репозитория.

```powershell
python -m pip install -r requirements.txt
python desktop_pet.py
```

## Новый сценарий — один файл

Скопируйте `examples/stretch.py` в `behavior_plugins/` и перезапустите приложение.
Он автоматически загрузится, попадёт в выбор автономных действий и станет
доступен через консольную команду `run stretch`. Регистрация, изменение
контроллера, перечислений состояний и других модулей не требуются.

Встроенные сценарии лежат в `src/behaviors/*.py` и обнаруживаются так же автоматически.
В EXE они включаются через `collect_submodules('behaviors')`. Внешние сценарии
читаются из `behavior_plugins/` рядом с EXE — их можно добавить без пересборки.
Сканирование выполняется при запуске; горячая перезагрузка не предусмотрена.

Минимальный сценарий:

```python
from animation_node import AnimationNode
from behavior_runtime import Scenario


class Behavior(Scenario):
    id = "look_around"

    @classmethod
    def weight(cls, controller):
        return 0.1

    def on_start(self):
        self.play(AnimationNode.ALERT)

    def on_animation_finished(self, node):
        if node == AnimationNode.ALERT:
            self.finish()
```

Каждый модуль экспортирует класс `Behavior(Scenario)` с уникальным `id`.
Новый экземпляр создаётся на каждый запуск. Храните фазу и локальное состояние
в полях этого экземпляра. Подпапки и файлы с именем на `_` не загружаются.
Совпадающие `id` не переопределяют существующий сценарий: ошибка записывается
в журнал, остальные скрипты продолжают загружаться.

| API | Назначение |
| --- | --- |
| `weight(controller)` | Вес в лотерее раз в 5 секунд, когда питомец свободен; `0` отключает участие |
| `probability(controller, event)` | Вероятность приоритетного запуска на событии `logic`; по умолчанию `0` |
| `priority` | Приоритет среди готовых к запуску сценариев и дополнительных триггеров |
| `interval_seconds = (min, max)` | Интервал автозапуска в секундах; по умолчанию `None` |
| `manager.postpone(id)` | Заново отсчитать интервал выбранного сценария |
| `on_start()` | Начало сценария |
| `on_tick()` | Обновление после физического движения, примерно раз в 16 мс |
| `on_animation_finished(node)` | Завершение одноразового клипа, включая переходные анимации |
| `on_animation_loop_finished(node)` | Конец полного оборота зацикленной анимации |
| `on_stop()` | Очистка собственных внешних эффектов при завершении, отмене или ошибке |
| `play(node, state=PetState.IDLE)` | Анимация с автоматическими переходами по графу |
| `later(ms, callback)` | Таймер, принадлежащий текущему запуску; автоматически отменяется при остановке |
| `finish()` | Завершение с возвратом в idle |
| `finish(go_idle=False)` | Завершение без запуска idle, например перед физическим падением |
| `manager.start(id)` | Переход из одного сценария в другой |
| `controller.start_behavior(id)` | Запуск извне с проверкой блокировки перетаскиванием, падением и меню |

Доступны `pet` (виджет/анимации), `motion` (движение),
`ctx` (общая физика и настройки), `controller`. Сценарии блокируют автономные
действия, пока не вызовут `finish()`. `blocks_cursor=True` по умолчанию блокирует
реакции на курсор. `preserve_on_menu=True` сохраняет сценарий при открытии
меню (так устроен hide). Перетаскивание отменяет текущий сценарий всегда.

Не добавляйте новые `is_*`-флаги в `PetContext`: активность определяется менеджером.
Атрибут `flags` нужен встроенным сценариям для совместимости с существующим UI.
Все callbacks выполняются в главном потоке Qt: они должны быстро возвращать
управление. Для задержек используйте `later`, а не `sleep` или неотменяемые
`QTimer.singleShot`. Таймер длительности фазы запускайте после появления нужного
узла анимации в `on_tick`, иначе переход будет съедать время самой фазы.

Ошибка импорта изолирует один файл; ошибка выполнения отключает сценарий до
перезапуска, отменяет его таймеры и возвращает питомца в idle. Скрипты не являются
песочницей — это локальный Python-код с правами приложения. Во внешнем скрипте
используйте стандартную библиотеку и зависимости, уже включённые в приложение.

Сценарий из одного файла комбинирует существующие анимации. Совершенно новая
поза дополнительно требует ресурсов и описания узла/переходов графа.
Замена существующих клипов поддерживает PNG-папки и спрайт-листы через
`assets/animations.json`: [инструкция по пиксельным анимациям](docs/ANIMATIONS.md).
Текущий пиксельный набор подключён через `assets/animations.json` с масштабом 3×.
Все узлы имеют ресурсы, часть использует временные подстановки:
[соответствия и недостающие рисунки](docs/ANIMATION_PACK.md).
Если запрошены отсутствующие кадры, сценарий отключается с диагностикой.

## Структура проекта

- `desktop_pet.py` — точка входа; команда запуска не изменилась.
- `src/` — код приложения; `src/behaviors/` — встроенные сценарии.
- `scripts/` — сборка релиза и генерация иконки.
- `packaging/` — настройки PyInstaller.
- `tests/` — тесты и проверка EXE.
- `examples/` — примеры внешних сценариев.
- `behavior_plugins/` — пользовательские сценарии.
- `assets/` — локальные изображения и анимации (не входят в Git).

`build/` и каталоги `__pycache__/` можно удалять: они создаются заново.
`dist/` содержит готовую сборку, `release/` — архивы релизов; их можно удалить,
если эти сборки больше не нужны. `.vs/` хранит локальное состояние Visual Studio.

## Архитектура

- `src/behavior_runtime.py`: загрузка, выбор сценариев, события, таймеры и отмена.
- `src/behaviors/`: отдельные сценарии, включая многофазные poop, run и hide.
- `src/pet_controller.py`: координация служб и входные события пользователя.
- `src/pet_cursor_ai.py`: специализированные реакции на курсор; использует общую
  блокировку активного сценария, поэтому новые сценарии не требуют правок здесь.
- `src/pet_motion.py`: перемещение, падение и приземление.
- `src/pet_animator.py`, `src/animation_graph.py`: маршруты и очередь анимаций.
- `src/animation_assets.py`: описание клипов, проверка ресурсов, PNG/спрайт-листы и кэш.
- `src/animation_player.py`: время кадров и сигналы воспроизведения.
- `src/app.py`, `src/pet_context_menu.py`: окно и элементы управления.

## Отладка и проверки

При запуске из интерактивного терминала: `behaviors` выводит сценарии и ошибки
загрузки; `run <id>` запускает выбранный сценарий; `show` показывает состояние.
Команда `schedule` показывает время до запланированных действий.
Сохранены `hide`, `hide`; любое действие запускается через `run <id>`.

```powershell
python -m pip install Pillow
python -m unittest discover -s tests -v
```

Тесты используют настоящий Qt без видимого окна и не требуют `assets/`.
Проверяются автозагрузка одного файла, приоритеты и блокировки, отмена таймеров,
ошибки скриптов, прерывания, фазы сценариев, расписание и очередь анимаций.

## Сборка

```powershell
python -m pip install -r requirements-build.txt
python scripts/build_release.py
```

Сборка запускается тем же интерпретатором и использует сохранённый `packaging/DesktopPet.spec`.
Скрипт больше не удаляет spec и не теряет настройки включения сценариев. Для
генерации иконки нужен `assets/icon.png`. Выход: `dist/DesktopPet` и ZIP в `release`.
На Windows окружение сборки ограничивает `PATH` интерпретатором и системными
каталогами: это предотвращает случайное включение несовместимых DLL других программ.

Проверка отдельной тестовой сборки без отображения окна:

```powershell
python tests/smoke_frozen.py path/to/test-build/DesktopPet.exe
```

Проверка временно добавляет один внешний скрипт рядом с EXE, запускает его через
автономный планировщик и удаляет после проверки. Используйте копию/тестовую сборку.

## Расписание поведения

Система потребностей удалена: нет сытости, энергии, настроения и мочевого пузыря.
Действия запускаются по времени с небольшим случайным разбросом:

| Сценарий | Интервал | Длительность |
| --- | --- | --- |
| Сон | 10–15 минут | 30–60 секунд после укладывания |
| Просьба о еде / царапанье | 4–7 минут | 1,8–3,5 секунды основного цикла |
| Туалет | 15–25 минут | прежняя последовательность с копанием и run |
| Hiding | 3–6 минут | выпрыгивание, наблюдение 5–10 секунд, упрыгивание |
| Точка когтей | 3–6 минут | подход к краю, цикл 4–8 секунд и завершение |
| Sandbath | 4–7 минут | укладывание, цикл 4–7 секунд, подъём |

Первый интервал выбирается при запуске приложения; новый — при каждом запуске
сценария, включая ручной. Планировщик проверяется раз в 5 секунд. Готовое действие
ждёт освобождения питомца, не прерывает другие действия, меню или перетаскивание.
Пропущенные периоды не накапливаются. Приоритет при одновременном ожидании:
туалет, сон, hide, просьба о еде. Между ними остаются случайные прогулки,
умывание, мяуканье и осмотр уведомлений.

Кормление запускается кликом в режиме FEED без проверки сытости; после него
таймер просьбы о еде отсчитывается заново. Повторный клик во время еды не
перезапускает анимацию. Во время сна, hide, падения и перетаскивания кормление
блокируется. В режиме FEED питомец не охотится на курсор. Реакции на обычный
курсор не зависят от настроения, реакция испуга ограничена временем.

Интервалы заданы в `interval_seconds` соответствующих `src/behaviors/*.py`.
Для нового сценария достаточно добавить этот атрибут; регистрация таймеров
в контроллере не нужна. Длительность сна задаётся `duration_seconds`.
Внешние сценарии, использовавшие `needs`, `on_needs` или
`interruptible_by_needs`, нужно перевести на `interval_seconds` и `later`.

Sleep разделён на вход 000–003, цикл дыхания 004–007 и выход 008–009.
Штатное пробуждение начинается на границе цикла; изменение положения тела
использует смену доступных поз (промежуточных рисунков в исходниках нет).

Если предыдущий DesktopPet запущен, сборщик сохраняет новую версию отдельно
в `dist/updated-*/DesktopPet/`, чтобы не очищать используемые файлы.

Умывание разделено на `start_clean → clean → end_clean`: подъём лапы,
2–5 секунд цикла и опускание лапы. Выход начинается на границе цикла,
сценарий завершается после `end_clean`.

Копание разделено на `start_dig → dig → end_dig`. И туалет,
и осмотр уведомлений завершают текущий оборот и выходной клип перед следующим
действием. Масштаб и длительности самих сценариев сохранены.

Подкрадывание разделено на `start_sneak → sneak → end_sneak`.
В sneak остаются только рабочие кадры 003–010; у цели манул сразу начинает
end_sneak и переходит к прыжку и копанию. При отмене он завершает оборот,
встаёт и возвращается в idle.

## Кормление

Кормление использует кадры `meow` в клипе `eat`, затем без промежуточного idle
переходит к `start_clean → clean → end_clean`. Повторные кормления во время
этой цепочки игнорируются. После мытья манул не принимает еду 60 секунд;
остальные действия доступны. Прерывание мытья после еды также запускает паузу.

## Охота на курсор

`swat` проигрывается один раз: курсор подтягивается к лапам до последнего
кадра, затем освобождается и манул возвращается в idle. После удара действует
пауза 5 секунд перед следующей реакцией на курсор. В цепочке `startle → swat`
удар также одноразовый, с тем же притягиванием и освобождением курсора.
Точка притягивания задана на передней лапе для каждого из 11 кадров;
масштаб и отражение учитываются. Захваченный курсор следует за движением лапы.

После 10 секунд неподвижности курсора в досягаемой зоне манул подкрадывается
и останавливается примерно в 90 пикселях перед целью. Сразу начинается
end_sneak, затем он прыгает к курсору: используются все 11 кадров «Прыжок»
с отдельной траекторией окна (подготовка → полёт по дуге → приземление).

При приземлении курсор перемещается под передние лапы. Во время подготовки
к копанию точка удержания следует за лапами; пружинное сопротивление совпадает
с механикой swat. Удержание ограничено 1,5 секунды, затем курсор свободен.
Манул копает на месте 2,5 секунды, заканчивает текущий оборот и end_dig,
после чего 60 секунд не реагирует на курсор. Остальные автономные действия
во время этой паузы доступны. Если мышь ушла далеко во время полёта, манул
копает без захвата и после завершения также теряет интерес на минуту.

Перетаскивание немедленно отменяет охоту, освобождает курсор и позволяет
подхватить манула в воздухе. Меню или смена действия отменяют захват/таймеры;
отмена полёта возвращает манула на землю. Все настройки охоты имеют префикс
`hunt_` в `src/pet_context.py`. Полёт, захват, копание и паузу обслуживает
`src/cursor_jump.py`; подкрадывание и обычный swat остаются в `pet_cursor_ai.py`.
Тесты охоты подменяют QCursor и не двигают реальную мышь.
